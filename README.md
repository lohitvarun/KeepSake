# Keepsake — Personal Diary & Memories

A local-first Flask + SQLite diary application using only Python, Flask, SQLite, HTML, CSS and vanilla JavaScript.

## Features included
- Sign-up with name, DOB (13+ validation), gender, email and password confirmation.
- Login using email and password; Werkzeug password hashing and session cookies.
- Private-by-default diary entries with editing, formatting toolbar, categories, tags, moods and folders.
- Entry search, pin/favourite/archive/trash actions, restore and permanent deletion.
- Dashboard with live counts, recent entries and estimated word count.
- Mood check-ins, memory cards with private uploads, events/timeline, goals, bucket list and writing prompts.
- JSON export and entry import, reminders, theme settings and profile editing.
- View-only token sharing links with optional expiry and revocation.
- Responsive light/dark UI.

## Run locally
1. Install Python 3.10 or newer.
2. Open a terminal in this folder.
3. Create a virtual environment (recommended):
   - Windows: `py -m venv .venv` then `.venv\\Scripts\\activate`
   - macOS/Linux: `python3 -m venv .venv` then `source .venv/bin/activate`
4. Install dependencies: `pip install -r requirements.txt`
5. Set a secret key before deployment:
   - Windows PowerShell: `$env:DIARY_SECRET_KEY="a-long-random-secret"`
   - macOS/Linux: `export DIARY_SECRET_KEY="a-long-random-secret"`
6. Run: `python app.py`
7. Open `http://127.0.0.1:5000`.

The SQLite database is created automatically at `database/diary.db`.

## Important production notes
- Set a strong `DIARY_SECRET_KEY`, turn off Flask debug mode, use HTTPS, and configure secure cookies.
- Use a persistent disk for `database/` and `uploads/` on hosting platforms.
- The share link is a bearer link: anyone who has it can view the entry until revoked or expired. Only share content you are comfortable sharing.
- Uploads are limited to 25 MB and use an extension allowlist. For a public deployment, add malware scanning and stricter content-type inspection.
- The rich-text editor stores HTML. The current version is intended for a trusted personal deployment; before public multi-user hosting, add HTML sanitization and CSRF protection (e.g. a vetted Flask CSRF extension). Do not expose this development build publicly with sensitive data until that hardening is completed.
- Browser theme preference is stored locally; the Settings page also saves a server-side theme choice.
- This starter does not implement audio recording, friend invitations, password-protected shares, PDF export, full calendar grid, offline sync, version history, or push notifications. Reminders are stored for reference and do not send background notifications.


## Deploy to Render (persistent SQLite + uploads)
This project includes `render.yaml` for a Render Blueprint deployment. It configures:
- A Python web service started with Gunicorn.
- `DIARY_SECRET_KEY` generated by Render.
- `DATA_DIR=/var/data`.
- A 1 GB persistent disk mounted at `/var/data` so the SQLite database and uploads survive restarts/deploys.

Because Render persistent disks require a paid web service, this configuration is **not a free deployment**. Do not remove the disk for a real diary: Render's default filesystem is ephemeral and can lose the database/uploads after restarts or deploys.

1. Push this project to a GitHub repository.
2. In Render, choose **New → Blueprint** and connect that repository.
3. Review the `keepsake-diary` service and its persistent disk, then apply.
4. Wait for the deploy to finish and open the `onrender.com` URL.
5. Create your account.

Before using real private diary content publicly, complete security hardening: add CSRF protection, sanitize stored rich-text HTML before rendering, enforce secure production cookie settings, and test backup/restore. This build is a starter and should not be treated as a hardened production service yet.
